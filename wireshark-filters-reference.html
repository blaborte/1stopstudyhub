01 IP & Host Filters —
📡 Display Filters — IP Address Matching ▼
Display filters are applied after capture in the Wireshark UI. They do not affect what is recorded — only what is shown. IP display filters are the most commonly used for isolating specific hosts in a capture file.
FilterTypeDescription
💡
Tip: ip.addr matches both source and destination. Use ip.src or ip.dst to be direction-specific. CIDR notation works: ip.addr == 10.0.0.0/8
🎣 Capture Filters — Host & Network ▼
Capture filters use BPF (Berkeley Packet Filter) syntax and are set before capturing starts. They reduce file size and resource usage by only recording matching traffic. Use these when you know exactly what you're looking for.
FilterTypeDescription
⚠️
Important: Capture filters cannot be changed mid-capture. When in doubt, capture everything and use display filters to analyze. BPF syntax differs from display filter syntax — host not ip.addr.

04 HTTP / Web Filters —
🌍 HTTP Request & Response Filters ▼
HTTP filters are display-only (HTTP is an application layer protocol). They're invaluable for web traffic analysis, hunting credentials in cleartext, tracing exfiltration, or debugging API calls. HTTPS/TLS requires decryption keys to inspect payload.
FilterTypeDescription
🎯
Security note: HTTP (port 80) traffic is unencrypted. Credentials, session tokens, and sensitive data can be extracted directly from captures. Always use HTTPS. Filter http.request.method == "POST" to hunt for credential submission over cleartext.
05 DNS Filters —
🔍 DNS Query & Response Filters ▼
DNS is a critical protocol to monitor for security. DNS tunneling, domain generation algorithms (DGA), and C2 beaconing all leave traces in DNS traffic. Wireshark's DNS dissector exposes query names, record types, and response codes.
FilterTypeDescription
⚠️
DNS Tunneling detection: Look for unusually long query names, high query volume to a single domain, or TXT record queries. Filter: dns.qry.type == 16 for TXT queries, and frame.len > 200 && dns for suspiciously large DNS packets.
06 TLS / SSL Filters —
🔒 TLS Handshake & Version Filters ▼
TLS filters are useful for identifying encryption versions, detecting weak cipher negotiation, and finding SNI hostnames without decrypting traffic. You can identify the destination domain from Client Hello even in encrypted sessions.
FilterTypeDescription
🔑
TLS versions: 0x0300 = SSLv3 (broken) · 0x0301 = TLS 1.0 (deprecated) · 0x0302 = TLS 1.1 (deprecated) · 0x0303 = TLS 1.2 · 0x0304 = TLS 1.3. Filter for old versions to find compliance gaps: tls.record.version < 0x0303
07 Operators & Logic —
⚙️ Filter Syntax — Operators & Comparisons ▼
Wireshark display filters support rich boolean logic and comparison operators. Combining filters with AND/OR/NOT lets you build precise expressions. Capture filters use BPF syntax with slightly different keywords.
Filter / OperatorTypeDescription
💡
Combining filters: ip.src == 10.0.0.1 && tcp.port == 443 — HTTPS from a specific host. http || dns — all HTTP or DNS. !arp && !icmp — exclude noise. Parentheses group: (ip.src==10.0.0.1 || ip.src==10.0.0.2) && tcp.port==80
08 TCP Flag Filters —
🚩 SYN, ACK, FIN, RST, PSH, URG ▼
TCP flag filters are essential for security analysis. Port scans, SYN floods, RST injection, and connection teardown patterns all reveal themselves through flag combinations. The hex bitmask approach lets you match exact flag states.
FilterTypeDescription
🎯
TCP 3-way handshake: SYN (0x002) → SYN-ACK (0x012) → ACK (0x010). A stream of SYN-only packets with no SYN-ACK response is a classic SYN scan (nmap -sS). An RST flood or many RST-ACK responses indicate connection refused or firewall blocking.
09 ARP & ICMP Filters —
📢 ARP Requests, Replies & ICMP Types ▼
ARP and ICMP are fundamental network protocols that also serve as common attack vectors. ARP spoofing, ARP poisoning, and ICMP-based reconnaissance are all detectable in Wireshark captures with the right filters.
FilterTypeDescription
⚠️
ARP Poisoning detection: Multiple ARP replies with different MAC addresses for the same IP, or gratuitous ARPs not following a reboot, are red flags. Filter: arp.opcode == 2 && arp.src.proto_ipv4 == 192.168.1.1 to watch for spoofed replies claiming a specific IP.
10 Advanced Analysis Filters —
🔬 Performance, Retransmissions & Anomalies ▼
Advanced filters surface performance issues, protocol anomalies, and forensic artifacts. Wireshark's expert analysis engine tags many of these automatically — the filters below let you isolate them programmatically for scripting and bulk analysis.
FilterTypeDescription
🔑
Performance triage flow: Start with tcp.analysis.retransmission to find packet loss → then tcp.analysis.zero_window for receiver bottlenecks → then frame.time_delta > 0.5 to find latency spikes. This three-step sequence diagnoses most TCP performance issues.
