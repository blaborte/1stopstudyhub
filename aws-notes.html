☁️ Cloud Computing Fundamentals ▼
Cloud computing is the on-demand delivery of IT resources over the internet with pay-as-you-go pricing. This is the single most important concept in the CLF-C02 exam — every other topic builds on it.
Six Advantages of Cloud Computing
  • Trade capital expense for operational expense: No upfront hardware purchases — pay only for what you use
  • Benefit from massive economies of scale: AWS buys at such scale it passes savings to customers
  • Stop guessing capacity: Scale up or down instantly — no over or under provisioning
  • Increase speed and agility: Deploy globally in minutes, not weeks or months
  • Stop spending money on data centers: Focus on your customers, not racking servers
  • Go global in minutes: Deploy to any AWS Region with a few clicks
Cloud Service Models

Cloud Deployment Models
  • Public cloud: All resources on AWS — most scalable and cost-efficient. No hardware to maintain.
  • Private cloud: Dedicated infrastructure for one organization — VMware Cloud on AWS.
  • Hybrid cloud: Combination of on-premises + AWS via Direct Connect or VPN. Most common enterprise approach.
  • Community cloud: Shared by organizations with common requirements (e.g., government agencies).
🎯
Exam Focus: Know all six advantages cold. The most commonly tested are: trade CapEx for OpEx, stop guessing capacity, and increase speed and agility.
🌍 AWS Global Infrastructure ▼
AWS's global footprint is one of its most significant advantages. Understanding Regions, AZs, and edge locations is essential — multiple CLF-C02 questions test this directly.
Infrastructure Components
  • AWS Regions: Geographic areas containing 2+ AZs. 30+ Regions worldwide (us-east-1, eu-west-1, ap-southeast-1). Each Region is independent — data does not automatically leave a Region.
  • Availability Zones: One or more discrete data centers within a Region, with independent power, cooling, and networking. Connected by high-bandwidth, low-latency links. Typically 3 AZs per Region.
  • Edge Locations: 400+ points of presence worldwide for CloudFront CDN caching and Route 53 DNS. Many more than Regions — bring cached content closer to users.
  • AWS Local Zones: Extensions of Regions to specific metro areas (e.g., Los Angeles, Dallas) for ultra-low latency workloads.
  • AWS Wavelength Zones: AWS infrastructure embedded in telecom carrier networks for 5G applications requiring single-digit millisecond latency.
How to Choose an AWS Region
  • Compliance: Data sovereignty laws may require data to stay in a specific country (GDPR in EU)
  • Latency: Choose the Region closest to your users for best performance
  • Service availability: Not all services are available in all Regions
  • Pricing: Prices vary slightly between Regions — us-east-1 (Virginia) is typically cheapest
💡
Memory aid: Region > Availability Zone > Data Center. Think of Regions as cities, AZs as neighborhoods, and data centers as individual buildings within each neighborhood.
🏗️ Well-Architected Framework & Design Principles ▼
The AWS Well-Architected Framework provides a consistent approach for evaluating cloud architectures. All six pillars appear in CLF-C02 exam questions.
Six Pillars
  • Operational Excellence: Run and monitor systems. Automate changes, respond to events, define standards. Focus on continuous improvement.
  • Security: Protect information and systems. Apply least privilege, enable traceability, protect data in transit and at rest.
  • Reliability: Recover from failures and meet demand. Test recovery procedures, scale horizontally, stop guessing capacity.
  • Performance Efficiency: Use resources efficiently. Use advanced technologies, deploy globally in minutes, use serverless architectures.
  • Cost Optimization: Avoid unnecessary costs. Adopt a consumption model, measure overall efficiency, stop spending on undifferentiated heavy lifting.
  • Sustainability: Minimize environmental impact. Maximize utilization, use managed services, right-size infrastructure.
Design Principles for Cloud
  • Design for failure: Assume everything fails. Build redundancy at every layer.
  • Decouple components: Use SQS, SNS to separate application tiers so failures are isolated.
  • Implement elasticity: Auto Scaling automatically adjusts capacity — never over-provision statically.
  • Think parallel: Break sequential work into parallel tasks. Use distributed systems.
🔑
Shared Responsibility Model: AWS manages security OF the cloud (physical, hardware, network, hypervisor). YOU manage security IN the cloud (OS, applications, data, IAM, encryption, network config).
Domain 2 Security & Compliance 25%
🔐 AWS IAM — Identity & Access Management ▼
IAM is the most tested security topic on the CLF-C02. You must understand users, groups, roles, policies, and the critical best practices AWS recommends.
Core IAM Components
  • Root user: Created with the AWS account. Has full unrestricted access. Enable MFA immediately. Never use for daily tasks. Do not create access keys.
  • IAM Users: Individual accounts for people or applications. Have long-term credentials (password + access keys). Best practice: one user per person.
  • IAM Groups: Collections of IAM users. Assign policies to groups, not individual users. Users inherit group permissions. Simplifies permission management.
  • IAM Roles: Identities with no permanent credentials — assumed temporarily. For EC2 instances, Lambda, cross-account access, federated users.
  • IAM Policies: JSON documents defining what actions are allowed/denied on which resources. Attached to users, groups, or roles.
IAM Best Practices
  • Enable MFA on the root account and all IAM users with console access
  • Follow principle of least privilege — grant minimum permissions needed
  • Use roles instead of sharing credentials for services and cross-account access
  • Create individual IAM users — never share credentials
  • Rotate access keys regularly and remove unused credentials
  • Use IAM Access Analyzer to identify unintended resource access

🛡️ AWS Security Services ▼
AWS provides purpose-built security services for threat detection, vulnerability assessment, DDoS protection, and data protection. Know what each service does and when to use it.
Threat Detection & Monitoring
Amazon GuardDuty
Intelligent threat detection using ML. Analyzes CloudTrail, VPC Flow Logs, DNS logs. Detects: account compromise, unauthorized access, crypto mining. No agents needed.
AWS CloudTrail
Records ALL API calls in your account — who, what, when, where. Essential for auditing and compliance. Enabled by default 90 days; create Trail for longer retention in S3.
Amazon Inspector
Automated vulnerability assessments for EC2 instances and container images. Identifies software vulnerabilities and unintended network exposure.
AWS Config
Tracks resource configuration changes over time. Evaluates resources against compliance rules. Answers: "What changed? When? Who changed it?"
Amazon Macie
Uses ML to discover and protect sensitive data (PII) in S3. Identifies public buckets, unencrypted data, and unusual access patterns.
AWS Security Hub
Centralizes security findings from GuardDuty, Inspector, Macie, and third-party tools. Provides compliance dashboard.
Protection Services
AWS WAF
Web Application Firewall — blocks SQL injection, XSS, bad bots. Works with CloudFront, ALB, API Gateway.
AWS Shield Standard
Free automatic DDoS protection for all AWS customers at Layer 3/4.
AWS Shield Advanced
Paid enhanced DDoS protection with 24/7 DRT access, cost protection, and application-layer defense.
AWS Firewall Manager
Centrally manage WAF rules, Shield, Security Groups across multiple accounts in AWS Organizations.
🔒 Encryption & Data Protection ▼
Encryption is a fundamental requirement for compliance and security. AWS provides managed services for key management and integrates encryption natively across most services.
AWS KMS (Key Management Service)
  • Creates and manages cryptographic keys for encrypting your data
  • Integrated with 100+ AWS services: S3, EBS, RDS, Lambda, CloudTrail, etc.
  • Customer-managed keys (CMK): You control key policy, rotation, and deletion
  • AWS-managed keys: AWS creates and manages on your behalf (less control)
  • Key rotation: Automatic annual rotation for customer-managed keys
  • FIPS 140-2 Level 3 compliant for regulatory requirements
Encryption Types
  • Encryption at rest: Data encrypted when stored on disk. S3 (SSE-S3, SSE-KMS, SSE-C), EBS volumes, RDS databases. Protects from physical disk theft.
  • Encryption in transit: Data encrypted while moving across networks. HTTPS/TLS, VPN connections, AWS Certificate Manager for SSL/TLS certs.
  • Client-side encryption: You encrypt data before sending to AWS. You manage keys. AWS never sees plaintext.
Network Security
  • Security Groups: Stateful virtual firewalls at the instance level. Allow rules only. Return traffic automatically allowed.
  • Network ACLs: Stateless subnet-level firewalls. Separate inbound and outbound rules. Explicit deny capability. Rules processed in order.
  • VPC Flow Logs: Capture IP traffic information flowing through VPC network interfaces. Used for security analysis and troubleshooting.
Domain 3 Cloud Technology & Services 33%
💻 Compute Services ▼
Compute is the engine of AWS. Understanding when to use EC2 vs Lambda vs containers is fundamental — the CLF-C02 tests your ability to choose the right compute service for a given scenario.
Amazon EC2
  • Virtual servers — rent compute capacity in the cloud. Full control over OS, software, networking.
  • Instance families: General Purpose (M, T), Compute Optimized (C), Memory Optimized (R, X), Storage Optimized (I, D), Accelerated (P, G — GPU)
  • EC2 Instance Store: Temporary block storage physically attached to the host — lost if instance stops or terminates
  • EBS volumes: Persistent block storage that survives instance stop/terminate
  • User Data: Shell script that runs once when instance first starts — for bootstrapping software
  • AMI (Amazon Machine Image): Template containing OS, applications, and config for launching EC2 instances

Serverless & Container Compute
  • AWS Lambda: Run code without servers. Event-driven. Pay per request + duration. Auto-scales. Max 15 min. 1M free requests/month.
  • AWS Fargate: Serverless compute for containers. No EC2 management. Pay per vCPU and memory used per task.
  • Amazon ECS: AWS-managed container orchestration using its own scheduler.
  • Amazon EKS: Managed Kubernetes — bring Kubernetes workloads to AWS without managing the control plane.
  • AWS Elastic Beanstalk: PaaS — upload code, Beanstalk handles everything else (EC2, LB, Auto Scaling, monitoring).
🗃️ Storage Services ▼
AWS offers multiple storage services optimized for different use cases. Choosing the right storage type is a key CLF-C02 exam skill.
Amazon S3 Deep Dive
  • Object storage — store any file up to 5TB as an object in a bucket
  • Globally unique bucket names — created in a specific Region, accessible globally via URL
  • 11 nines durability (99.999999999%) — data replicated across 3+ AZs automatically
  • Versioning: Keep multiple versions of an object — protects against accidental deletion
  • Lifecycle policies: Automatically transition objects to cheaper storage classes after N days
  • S3 Transfer Acceleration: Upload files faster using CloudFront edge locations
  • Static website hosting: Host a static website directly from S3
  • Cross-Region Replication: Automatically copy objects to another Region for DR

Other Storage Services
  • Amazon EBS: Block storage for EC2 — like a virtual hard drive. AZ-specific. gp3 (SSD, general), io2 (high IOPS), st1 (HDD, throughput), sc1 (HDD, cold).
  • Amazon EFS: Managed NFS file system — shared across thousands of EC2 instances simultaneously. Scales automatically. Multi-AZ.
  • AWS Storage Gateway: Hybrid storage — connects on-premises environments to AWS storage (S3, Glacier). Types: File, Volume, Tape.
  • AWS Snowball: Physical device (appliance) to migrate petabytes of data to AWS when network transfer is too slow. Snowball Edge adds compute capability. Snowmobile: truck for exabyte-scale.
🌐 Networking & Database Services ▼
VPC networking and database selection are core CLF-C02 topics. Know the difference between relational and NoSQL databases, and understand VPC components.
VPC Key Components
  • VPC: Your private network in AWS. Define CIDR block (e.g., 10.0.0.0/16). Spans all AZs in a Region.
  • Subnets: Subdivisions of a VPC. Public subnet: has route to Internet Gateway. Private subnet: no direct internet access.
  • Internet Gateway (IGW): Enables internet access for VPC resources with public IPs.
  • NAT Gateway: Allows private subnet instances to access the internet without being reachable from outside.
  • Security Groups: Stateful firewall at instance level — allow rules only, return traffic auto-allowed.
  • NACLs: Stateless firewall at subnet level — separate inbound/outbound rules, can deny.
  • VPC Peering: Private connectivity between two VPCs — no internet, no bandwidth bottleneck.
  • AWS Transit Gateway: Hub-and-spoke model to connect many VPCs and on-premises networks through one gateway.
  • VPC Endpoints: Connect to AWS services (S3, DynamoDB) privately without internet, NAT, or VPN.
Database Services
Amazon RDS
Managed relational databases — MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Aurora. Handles patching, backups, Multi-AZ failover, read replicas.
Amazon Aurora
AWS-built relational database — MySQL/PostgreSQL-compatible. 5x faster than MySQL, 3x faster than PostgreSQL. 6 copies across 3 AZs. Serverless option available.
Amazon DynamoDB
Fully managed NoSQL — key-value and document. Single-digit millisecond latency at any scale. Serverless — no capacity planning. DAX = in-memory cache.
Amazon Redshift
Petabyte-scale data warehouse for analytics. Columnar storage. SQL-based. Used for BI/reporting, not transactional workloads.
Amazon ElastiCache
Managed in-memory cache — Redis or Memcached. Sub-millisecond latency. Reduces database load for frequently accessed data.
Amazon DMS
Database Migration Service — migrates databases to AWS with minimal downtime. Supports homogeneous (MySQL to RDS MySQL) and heterogeneous migrations.
⚙️ Additional AWS Services ▼
The CLF-C02 tests awareness of a broad range of AWS services. You do not need to know how to configure them — just understand their purpose and use case.
Developer & Deployment Tools
  • AWS CloudFormation: IaC — define infrastructure in JSON/YAML templates. Repeatable, consistent, version-controlled deployments.
  • AWS CDK: Cloud Development Kit — define CloudFormation resources using Python, TypeScript, Java, or .NET code.
  • AWS CodePipeline: Continuous delivery pipeline — automate build, test, deploy.
  • AWS CodeBuild: Managed build service — compiles source code, runs tests, produces artifacts.
  • AWS CodeDeploy: Automates application deployments to EC2, Lambda, on-premises.
  • AWS Systems Manager: Manage EC2 and on-premises systems at scale — patch management, parameter store, session manager (SSH-less access).
Analytics & AI/ML
  • Amazon Athena: Query data directly in S3 using SQL — serverless, pay per query.
  • Amazon Kinesis: Real-time data streaming — ingest and process streaming data.
  • AWS Glue: Managed ETL service — discover, transform, and load data for analytics.
  • Amazon QuickSight: Business intelligence service — create dashboards and visualizations.
  • Amazon SageMaker: Build, train, and deploy ML models at scale — no ML infrastructure management.
  • Amazon Rekognition: AI image and video analysis — facial recognition, object detection.
  • Amazon Comprehend: NLP — extract insights from text (sentiment, entities, key phrases).
  • Amazon Lex: Build conversational interfaces (chatbots) using voice and text.
Messaging & Integration
  • Amazon SQS: Message queue for decoupling services. Standard (best-effort ordering) or FIFO (exact ordering, deduplication).
  • Amazon SNS: Pub/sub notification service. Publishers send to topics; SNS fans out to subscribers (email, SMS, Lambda, SQS, HTTP).
  • Amazon EventBridge: Serverless event bus — connect applications using events. Route events from AWS services, SaaS, and custom apps.
  • AWS Step Functions: Coordinate distributed applications as visual workflows — orchestrate Lambda, ECS, and other services.
💡
Quick reference: Decouple = SQS. Notify many = SNS. Stream in real-time = Kinesis. Query S3 = Athena. ML models = SageMaker. IaC = CloudFormation.
Domain 4 Billing, Pricing & Support 16%
💰 AWS Pricing Models & Cost Tools ▼
Understanding AWS pricing is one of the most practical CLF-C02 skills. Know the pricing models, the cost management tools, and how to reduce AWS spend.
Core Pricing Principles
  • Pay-as-you-go: Pay only for what you use, no minimum fees, stop paying when you stop using
  • Save when you reserve: Reserved Instances and Savings Plans provide discounts for commitment
  • Pay less as you use more: Volume discounts — S3, data transfer, DynamoDB all get cheaper at scale
  • AWS Free Tier: Always-free (Lambda, DynamoDB), 12-month free (EC2, S3, RDS), and trial offers

Cost Management Tools
AWS Pricing Calculator
Estimate future monthly costs BEFORE building. Configure services and get detailed breakdown. Free to use. Share via public URL.
AWS Cost Explorer
Visualize past spending. Interactive graphs by service, region, account, tag. Rightsizing recommendations. 13 months of history. Forecast future costs.
AWS Budgets
Set cost, usage, RI, or Savings Plans budgets. Alerts when actual or forecasted exceeds threshold. Automated actions on breach (stop EC2, apply SCP).
AWS Cost & Usage Report
Most detailed billing data available. Hourly line items per resource. Delivered to S3. Analyze with Athena or QuickSight.
AWS Trusted Advisor
Checks for idle resources, underutilized EC2, unassociated Elastic IPs, non-reserved capacity. Cost optimization recommendations.
Cost Allocation Tags
Tag resources (Project=X, Env=Prod) and view costs broken down by those tags in Cost Explorer. Must be activated in Billing console.
🏢 AWS Organizations & Support ▼
AWS Organizations helps manage multiple accounts centrally. Support plans determine what level of help you get from AWS. Both are directly tested on the CLF-C02.
AWS Organizations
  • Consolidated Billing: Single bill for all accounts. Share volume discounts across all accounts. Free data transfer within the organization.
  • Management account: Master account that pays all charges and manages the organization.
  • Service Control Policies (SCPs): Guardrails that restrict what actions can be taken in member accounts — even by administrators. Cannot override to grant MORE access.
  • Organizational Units (OUs): Group accounts for policy application — e.g., Production OU, Development OU.
  • AWS Control Tower: Automates setting up and governing a secure multi-account environment with pre-configured guardrails.

Other Cost Optimization Strategies
  • Right-sizing: Match instance type to actual workload requirements — use Cost Explorer rightsizing recommendations
  • Turn off unused resources: Stop EC2 instances outside business hours, delete unattached EBS volumes
  • Use managed services: RDS, Lambda, DynamoDB eliminate OS/server management overhead costs
  • S3 Lifecycle policies: Automatically move data to cheaper storage classes based on age
  • Reserved Instances: For predictable workloads, commit and save up to 72%
  • AWS Compute Optimizer: ML-based recommendations for right-sizing EC2, Lambda, EBS, ECS
